# 배포 — Railway CLI 로컬 업로드 (2026-08-06 확정)

제출은 링크 제출 형식이고 내 PC 를 계속 켜 둘 수 없으므로 호스팅에 올린다.
링크 소지자만 플레이하므로 API 비용 노출은 감수한다 (대신 아래 지출 한도 필수).

## 왜 Railway 인가

이 게임의 구조가 선택지를 좁힌다. 셋 다 실측·코드로 확인한 사실이다.

| 제약 | 탈락하는 옵션 |
| --- | --- |
| 세션이 전부 **인메모리 Map** (`src/server/session.js` 머리말) + SSE 스트리밍 | Vercel·Netlify — 서버리스는 요청마다 인스턴스가 갈릴 수 있어 세션이 끊긴다 |
| 그림 **571개가 Git LFS** (`.gitattributes`) | Render 등 GitHub 연동 빌더 — LFS 미지원이라 포인터 텍스트를 받아 화면이 통째로 빈다 |
| 심사위원이 링크 클릭 → 즉시 떠야 함 | 무료 슬립 티어 — Render 무료는 유휴 15분 후 콜드 스타트 ~50초, 죽은 페이지로 보인다 |

`railway up` 은 **로컬 디렉터리를 그대로 업로드**한다 — LFS 가 이미 실파일이라 안전하고,
상시 가동이라 슬립이 없다. Hobby $5/월(가입 체험 크레딧 $5). 차선은 Fly.io(같은
로컬 업로드 방식, 설정이 조금 더 많다).

## 이미 준비된 것 (2026-08-06 검증)

- **코드는 수정 없이 올라간다.** `NODE_ENV=production` 로컬 실행으로 확인:
  게임 페이지·초상 200 · `/api/health` OK · `/api/studio/*` 403(파일 쓰기 차단) ·
  `PORT` env 대응 · SPA 폴백. Railway(nixpacks)가 `npm run build` → `npm start` 를
  자동으로 돈다 (package.json 의 scripts 그대로).
- **`.railwayignore`** — design/(118MB)·docs/·dist/ 제외. 업로드 ~60MB.
  public/(초상·UI·인트로 영상)과 src/ 는 런타임 필수라 제외하면 안 된다.

## 배포 절차 (~5분)

```bash
npm i -g @railway/cli
railway login                    # 브라우저 로그인 (대화형)
railway init                     # 새 프로젝트 생성
railway variables --set "ANTHROPIC_API_KEY=sk-ant-..."
railway up                       # 업로드 + 빌드 + 기동
railway domain                   # https://xxx.up.railway.app 발급 → 이게 제출 링크
```

## 제출 전 체크리스트

1. **`REVEAL_ANSWER` 는 설정하지 않는다** — 심사위원이 백틱(`) 키로 정답을 본다.
2. Anthropic 콘솔에 **지출 한도**를 걸어 둔다 — 링크가 새어도 상한이 막는다.
3. **심사 기간 중 재배포 금지** — 인메모리 세션이라 재시작하면 진행 중인 판이 전부
   끊긴다. 마감 전에 올리고 그대로 둔다.
4. 올리기 전에 작업 브랜치를 master 에 병합해 둔다 — `railway up` 은 **지금 체크아웃된
   워킹 트리**를 올린다 (git 상태와 무관하게 디스크의 파일 그대로).
5. 배포 후 `https://<도메인>/api/health` 에서 `hasApiKey: true` 확인.
6. 링크 첫 클릭부터 엔딩까지 한 판 직접 완주해 본다 — 특히 스테이지 1 시작의
   LLM 대기(11~20초)가 로딩 화면으로 덮이는지.
