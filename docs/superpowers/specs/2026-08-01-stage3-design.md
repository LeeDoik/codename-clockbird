# 스테이지 3 설계서 — 저택 탈출 + 신형 로봇 심문

- 작성일: 2026-08-01
- 근거: 8/1 팀 합의 — "스테이지 3 컷" 기각. 게임을 어필할 때 3스테이지까지 나오는 편이 낫다(이도익) + 마지막 로봇 1:1 심문을 살리고 싶다(park seung soo)
- 마감: 기능 동결 8/7, 제출 8/10. **실질 개발은 8/4까지 3일**
- 선행: 스테이지 2 축소(열쇠 보유자 무작위 1인) 구현·스모크 통과 — 확보한 시간을 여기로 넘긴다

## 1. 배경과 목표

계획서 §4.5가 스테이지 3을 "잠입 파트 + 심문 미니게임"으로 정의해 뒀고, §2는 **심문 미니게임을 사수 라인**(튜토리얼 + 스테이지 1 + 심문)으로 못박았다. 스테이지 3은 이 저장소에서 유일하게 아직 존재하지 않는 스테이지다.

어필 축은 **"생성형 AI를 대화 풍성함이 아니라 스테이지마다 다른 클리어 조건으로 썼다"** 이다.

| 스테이지 | AI가 담당하는 클리어 조건 |
|---|---|
| 튜토리얼 | 힌트 해석 |
| 스테이지 1 | 암호 역추론 + 정답 판정 |
| 스테이지 2 | 성향 판정 |
| **스테이지 3** | **신분 연기 심문 (이중 판정)** |

### 확정된 결정

| 쟁점 | 결정 |
|---|---|
| 탈출 파트 깊이 | **계획서대로 발각 게이지 + 엄폐** (통로만 통과 / Patrol 재사용 안은 기각) |
| 감지 형태 | **시야 콘 + 지형 차단** (원형 감지기 + 능동 은신 안은 기각) |
| 맵 구조 | **정통 ㄹ자 5구간 / 굽이 4** (3구간 축약안, 지름길 분기안은 기각) |
| 발각 시 처리 | **검문·QTE 없이 즉시 리셋.** 결과 화면 안 띄움 |
| 재시작 지점 | **구간 체크포인트 5곳** (맵 처음부터 / 게이지 회복만 안은 기각) |
| 심문 길이 | **8문 상한 + 추리 선언** (계획서 15문에서 하향) |
| 신분 단어 | **고정 풀 무작위 3개** (LLM 생성 기각 — 시작 지연) |
| 엔딩 | **본부 귀환 씬** (정적 카드 / 영상 안은 기각) |

### 기각 이유 기록

- **시야 콘**: `Patrol.js`(18~24행)가 콘을 의도적으로 기각한 이력이 있다 — "등 뒤에 붙어 따라다니는 것이 최적 전략"이 되어서다. 그러나 그건 60×48 열린 거리 맵의 문제고, **폭 5칸 통로에서는 로봇 뒤로 돌아갈 공간 자체가 없어** 그 악용이 성립하지 않는다. 콘을 되살리되 적용 범위를 통로로 한정한다.
- **15문 → 8문**: 턴당 LLM 왕복 약 3초 + 플레이어 타이핑 약 10초 = 턴당 13초. 15문이면 심문만 3분 15초로 **제출 영상 3~5분을 심문 하나가 다 먹는다.** 8문이면 약 1분 45초.
- **맵 처음부터 재시작**: 실수 한 번에 1분 30초를 통째로 다시 걷게 된다. 팀이 우려한 "루즈함"이 정확히 여기서 나온다.

## 2. 씬 구조와 연결

**씬은 하나다.** 탈출과 심문을 각각 씬으로 쪼개지 않는다. 심문은 `MinigamePanel` DOM 오버레이로 띄우면 되고 `StageScene`이 검문을 이미 그렇게 처리한다. 씬을 나누면 카메라·HUD·페이드를 두 벌 관리하게 된다.

### 이어붙이는 지점 3곳

1. **`MansionScene.#endGame('document')` → `#toEscape()`로 분기.**
   `StageScene.#toMansion`(StageScene.js:762) 패턴을 그대로 미러링한다 — 대사 비트 → `cameras.main` · `uiCam` · `hud` 동시 페이드아웃 900ms → `camerafadeoutcomplete`에서 `scene.start('Escape')`.
   **밀고·게임오버 경로는 기존 `ResultOverlay`를 유지한다** (이야기가 끊기는 자리가 맞다).
2. **`EscapeScene` 심문 승리 → 같은 페이드 패턴 → `scene.start('Ending')`.**
3. **`EndingScene`** — `TutorialScene`의 hq 맵·브란트 아트·대화 체계를 재사용한 축소판. 간부에게 걸어가 `[E]` 보고 → "반격의 서막" → To be continued.

### `Patrol.js`를 재사용하지 않는 이유

`Patrol`은 `map.json`을 직접 import하고 `PATROL_ROUTES`에 거리 맵 좌표가 하드코딩돼 있다. 범용화하려면 스테이지 1을 건드려야 하는데 거긴 사수 라인이고 `check-spawn-safety.js`로 검증된 상태다. 대신 **LOS 광선 판정만 `world/los.js`로 추출해 `Patrol`·`Sentry`가 공유한다** — 순수 함수 이동이라 `Patrol` 동작은 변하지 않는다.

### 개발 플래그

`?stage3`. 단, **서버 상태를 바꾸는 플래그는 시작 요청에 실어 보낸다.** `?stage2&key`가 클라이언트에만 열쇠를 세워 `/document`가 409로 거절했던 함정을 반복하지 않는다.

## 3. 탈출 파트

### 맵 `escape.json` — 60×34칸 (배경 1920×1088)

60칸 폭은 이 저장소의 맵 규격이다(`mansion.json` 60×35, `hq.json` 60×40). **메인 카메라가 2배 줌이라 한 화면에 보이는 월드는 960×540px = 30×17칸이다**(`main.js:11-13`, `worldParts.setupCameras`). 따라서 60×34는 가로·세로 각각 두 화면짜리 스크롤 맵이고, 배경 이미지는 60×34×32px = **1920×1088**이다. 통로 폭 5칸(160px).

| 구간 | 영역 | 이동 |
|---|---|---|
| ① 상단 | rows 2–6, cols 2–50 | → 우 |
| ② 우측 수직 | cols 46–50, rows 2–16 | ↓ |
| ③ 중단 | rows 12–16, cols 5–50 | ← 좌 |
| ④ 좌측 수직 | cols 5–9, rows 12–27 | ↓ |
| ⑤ 하단 | rows 23–27, cols 5–52 | → 우 |
| 심문실 | cols 48–58, rows 20–31 | 꼬마 조우 |

총 경로 약 157칸(5,000px). 플레이어 200px/s 기준 순수 이동 25초 + 엄폐 대기 3회 ≈ **1분 내외**.

**이동 경로는 한 줄이라 길을 잃을 수 없다.** 난이도는 순찰 주기와 엄폐물 간격으로만 조절한다 — 미로를 만들지 않는 것이 "아주 단순한 탈출맵"이라는 8/1 합의의 핵심이다.

### 시야 콘

- 각 **70°**, 길이 **220px**(약 7칸). 바닥에 반투명으로 그린다
- `world/los.js` 광선(8px 간격, `Patrol`의 `LOS_STEP`과 동일)이 벽과 엄폐물에 막혀 콘을 잘라낸다

### 발각 게이지

게이지가 둘이라 이름을 나눠 쓴다 — 탈출은 **발각 게이지**(0에서 시작해 오르고 100에서 터짐), 심문은 **탐지 게이지**(100에서 시작해 내려가고 0에서 터짐, §4). 방향이 반대이므로 코드·UI에서 절대 같은 이름을 쓰지 않는다.

발각 게이지는 0에서 시작해 **100에서 터진다**.

| 상황 | 변화 |
|---|---|
| 콘 안 + LOS 통과 | **+55/초** (약 1.8초 노출이면 만충) |
| 콘 밖 | **1초 유예 후 −40/초** (약 2.5초면 회복) |

유예 1초를 두는 이유: 콘 경계에서 게이지가 깜빡이며 오르내리면 플레이어가 규칙 자체를 못 읽는다.

HUD는 상단 얇은 바 + 게이지 상승 중 화면 가장자리 적색 비네트.

### 로봇 3기

구간당 1기. 속도 **90px/s**(플레이어 200의 45%) — 정면으로 마주쳐도 뒤로 빼서 엄폐물까지 갈 수 있어야 한다. 순찰 폭 24칸(768px)으로 **왕복 약 17초**, 끝점에서 1.5초 정지하며 콘이 회전한다.

### 엄폐물

**별도 개념이 아니다.** `escape-props.json`의 solid 사각형이 곧 콘 차단이다. 구간마다 2개씩, 순찰 축이 아닌 벽 쪽에 붙인다.

### 체크포인트 · 재시작

5구간 진입점 5개를 상수 배열로 둔다. 발각 시:

1. 0.4초 정지 + 적색 플래시
2. 0.8초 페이드
3. 직전 구간 입구에 리스폰
4. **해당 구간 로봇의 순찰 위상을 시작점으로 리셋**
5. 1.5초 미감지 유예

**`ResultOverlay`를 띄우지 않는다.** 재시도 총 소요 약 2.7초.

4번이 핵심이다. 순찰 위상을 리셋하지 않으면 "리스폰하자마자 코앞에 로봇"이 반복돼 정확히 루즈해진다.

시도 횟수는 세서 HUD에 조용히 표시만 한다 (밸런싱·영상용, 페널티 없음).

### 권위

**탈출 파트는 전부 클라이언트 계산이다.** 서버 왕복 없음 — `StageScene`의 순찰 감지와 같은 패턴이고, 실시간 이동에 서버 왕복을 넣을 수는 없다. 서버는 심문에서만 개입한다.

## 4. 심문 파트

### 흐름

1. 심문실 진입 → 꼬마 대사 → *"사실 나는 로봇이야"* → 심문 개시
2. `POST /api/escape/interrogation/start` → 신분 카드 3장. **탐지 게이지 100에서 시작**
3. 플레이어가 1장 선택 → 서버 `session.identity`에 저장
4. **8문 루프**: 질문 생성 → 플레이어 자유 입력(120자) → 판정 → 탐지 게이지 감산 + 로봇 대사
5. 종료 — 탐지 게이지 0 = 패배 / 추리 선언 적중 = 패배 / 8문 방어 = 승리

### 이중 판정

매 턴 서버가 **서로 다른 컨텍스트로 두 판정을 병렬 실행한다.** `stance.js`가 대화 스트림과 나란히 도는 것과 같은 패턴이라 지연은 합이 아니라 둘 중 최댓값이다.

| 판정자 | 아는 것 | 판정 | 감점 |
|---|---|---|---|
| 시스템 AI | 선택 단어를 **앎** | 단어와 어긋난 거짓 진술 | −20 |
| | | 단어를 **직접 노출** | −20 |
| 로봇 AI | 선택 단어를 **모름** | 이전 답변과 명시적 상충 | 첫 회 사면, 이후 −50 |
| | | 확신도 0~100 갱신 | — |

거짓도 위험하고 지나친 진실도 위험한 양면 긴장을 규칙으로 성립시킨다.

**첫 모순 사면**: 로봇이 지적하고 해명 기회를 1회 준다(감점 없음). LLM 오탐 1회를 규칙이 흡수하면서 동시에 긴장 연출이 된다.

### 정보 격리 — 어필의 실체

**로봇 판정기에게 `identity`를 절대 넘기지 않는다.** 서버가 두 호출의 컨텍스트를 따로 조립한다. 이 저장소가 이미 쓰는 "모르는 것은 유출될 수 없다" 원칙 그대로이고, 이게 없으면 이중 AI는 그냥 호출 두 번일 뿐이다.

**이 항목은 어떤 컷 상황에서도 건드리지 않는다.**

### 추리 선언

로봇 판정기가 매 턴 확신도 0~100을 반환한다. 서버는 **지금까지의 최댓값을 유지한다**(단조 증가) — 턴마다 값이 출렁이면 선언 타이밍이 운에 좌우된다.

확신도가 **70** 이상이면 선언한다(최대 **2회**). 로봇은 후보 3개를 모르니 자유 추측이고, 적중 판정은 기존 `ai/judge.js`(동의어 인정)를 재활용한다. 빗나가면 잔여 −1, 심문 계속.

로봇이 후보 3개를 알면 3지선다 소거법으로 필승이고, 모른 채 무제한 추리면 죽은 규칙이 된다. "비공개 + 제한 선언"이 양쪽 붕괴를 피한다.

### 모델 분담

계획서 §5.1 표 그대로 — **질문 생성 Haiku, 판정·추리 Sonnet.** `checkpoint.js`가 정확히 그 분담이라(질문 생성을 Haiku로 내려 지연 절반 이하를 실측) 구조를 옮겨 쓴다.

### 신분 단어

`src/data/escape.json` **고정 풀에서 무작위 3개**를 뽑는다. 배달부·정비공·청소부·요리사·정원사·세탁부·마부·짐꾼 등 12~15개.

- 카테고리는 **신분으로 연기 가능한 것(직업·역할)** 으로 한정한다. "선택 단어와 어긋난 거짓" 판정이 성립하려면 단어가 연기의 대상이어야 한다
- LLM 생성을 쓰지 않는 이유: 심문 시작에 LLM 대기가 붙는다(저택이 대기 없이 시작하는 것과 같은 원칙). 어필 포인트는 단어 뽑기가 아니라 판정 쪽이다

### fail-open

판정 호출이 실패하면 **감점 0으로 넘긴다.** `checkpoint.js`가 이미 그렇게 하고, API 장애로 지면 플레이어는 자기가 뭘 잘못했는지 알 수 없다. 시연이라면 그대로 사고다.

### 권위

`identity` · 게이지 · 모순 이력 · 선언 잔여는 전부 서버 소유. 클라이언트는 게이지 숫자와 로봇 대사만 받는다. 플레이어 본인은 자기가 고른 단어를 알아도 되고, **로봇만 모르면 된다.**

### UI

`MinigamePanel` 재사용. 카드 3장 → 질문 + 자유 입력(`interrogation.js`의 `askAnswer` 구조 그대로, IME 조합 중 Enter를 막는 `!e.isComposing` 규칙 포함) → 게이지 바 + 로봇 대사.

**순서 원칙: 임시 아트로 동작을 먼저 확정하고 나중에 갈아끼운다.** 배경과 충돌이 분리돼 있어(`worldParts.buildColliders` + `props.json`) 교체가 싸다. 다만 **이미지 생성은 대기가 길어 8/2에 착수**해야 8/4에 안 몰린다.

### 프롬프트 스튜디오 (2026-08-02 추가)

팀원이 프롬프트와 성격을 직접 조율할 수 있어야 한다는 요구가 붙었다. 확인해 보니 **서버 API 는 진작부터 템플릿 9종 전부 저장할 수 있었는데 UI 가 둘만 노출**하고 있었다 — 스테이지 2 프롬프트 4종은 "API 는 되는데 화면이 없어서" 못 고치는 상태였다.

- **프롬프트 UI 일반화 — 완료** (커밋 `0a99897`). `templateNames()` 순회 탭으로 바꿔 9종 전부 편집 가능. 새 템플릿을 `TEMPLATES` 에 넣으면 화면은 손대지 않아도 탭이 는다 — **S3 프롬프트 3종이 그렇게 자동으로 붙는다.** 탭마다 치환 변수와 경고를 붙였고, 경고는 전부 이미 부딪힌 함정이다 (wordgen 중복 폭등 · mansion 내부 수치 유출 · **escape-robot-judge 에 신분 단어 금지**).
- **저택 NPC 8인 성격 편집** — 계획 Task 14. `mansion.json` 의 `npcs[]` 를 스튜디오가 읽고 쓴다. `kind` 는 탭에 표시하되 편집 대상에서 뺀다 (맵 배치·`rewards` 와 얽혀 있어 여기서 바꾸면 조용히 어긋난다).
- **꼬마 성격을 데이터로** — 계획 Task 15. 프롬프트 본문에 박힌 성격을 `escape.json` 의 `child.backstory`/`personality` 로 빼서 S1·S2 와 같은 방식으로 맞춘다.

### 짚어둘 자원 충돌

저택 NPC 8인 아트가 아직 미완인데 위 일정과 같은 3일을 놓고 경쟁한다. 스테이지 3을 살리기로 한 이상 **S3 아트가 먼저**다 — S2는 지금도 플레이는 되지만 S3는 아예 없다.
