# 스테이지 개선 설계서 — 상호작용 연출 · 대화 v2 · S1/S2 개선

- 작성일: 2026-07-29
- 근거: 기획자 플레이 피드백 ("스테이지 2가 대화만 하다 보니 심심하다")
- 마감: 기능 동결 8/7, 제출 8/10

## 1. 배경과 목표

기획자 피드백 요지:

- **공통**: 상호작용 가능한 대상에 접근하면 말풍선(`Press E`)이 뜨고, 버튼을 눌러 상호작용. 일반 NPC / 선택지 NPC / 문 / 문서 유형별 동작 정의.
- **대화 연출**: 대사창 2줄 고정 + 버튼으로 넘기기. 선택지는 대화 상자 내부가 아니라 우측 별도 버튼 (최대 3개, 키 라벨 병기).
- **스테이지 1**: 진행 방향 유지. 동료는 "숨어 있다"는 느낌의 레벨 디자인. 정답 제출은 접선책 1명이 아니라 아무 동료에게나. 문제 출제는 dialogtest 브랜치 방식(더 쉬웠음).
- **스테이지 2**: 대화가 단조롭고, 직접적으로 말해도 신고/동료 확인이 안 뜸. 프롬프트를 다듬고 오브젝트 상호작용 추가.

### 확정된 결정

| 쟁점 | 결정 |
|---|---|
| 2줄 페이징 적용 범위 | 고정 대사·LLM 대사 **전부** 2줄 페이징 (LLM은 버퍼링 후 분할) |
| S2 오브젝트의 역할 | **대화 힌트 연동** — 조사로 단서 획득 → 관련 NPC와 대화에서 꺼내면 호감도 보너스 |
| S1 문제 출제 | dialogtest 브랜치 방식 채택 (backstory/personality 분리, 성격별 난이도 편차) |
| S1 구제책 | **미도입** — 플레이테스트 후 재검토 항목으로만 기록 |
| 정답 제출 | 아무 동료에게나 가능 (접선책 고유 역할 제거) |
| 맵 디자인 | 계획서에 구체 제안안 포함, 기획자와 제안 기반으로 논의 |
| 구현 접근 | **A. 공통 인터랙션 레이어 + 대화창 v2** (씬별 패치·콘텐츠 우선안 기각) |

## 2. 공통 인터랙션 레이어

신설: `src/client/world/interact.js`

상호작용 대상을 유형이 있는 노드로 등록하는 공용 매니저. 씬은 노드 등록만 하고 감지·말풍선·키 분기는 레이어가 처리한다.

### 노드 유형과 동작

| 유형 | E 동작 | 비고 |
|---|---|---|
| `npc` | 입력된 대사 출력 (2줄 페이징) | 일반 NPC |
| `choiceNpc` | 기본 대사 + 우측 선택지 버튼 | 선택지 최대 3개, 노드 데이터로 정의 |
| `door` | 열쇠 없음 → "잠겨 있다. 열쇠가 필요할 것 같다." / 있음 → "문이 열렸다." + 개방 | 저택 실험실 문이 첫 적용 (현행 자동 개방 → E 상호작용으로 변경) |
| `document` | 종이 질감 전용 패널로 문서 열람 | 대화창과 연출 분리 |
| `object` | 짧은 단서 텍스트 + 세션 플래그 기록 | S2 조사 오브젝트 |

### 말풍선

- 매 프레임 사거리 내 최근접 노드 1개에 머리 위 말풍선 표시: `[E]` 키 아이콘 + 짧은 동사 라벨("대화", "조사", "열기", "열람").
- Phaser 월드 오브젝트로 구현 (카메라 추적). 현행 "대화창에 안내 문자열 띄우기"(`StageScene.js`의 proximityHint 방식)는 제거.
- 세 씬(튜토리얼·거리·저택) 모두 이 레이어로 마이그레이션 — 튜토리얼에서 가르친 조작이 전 스테이지에서 동일하게 유지된다.

## 3. 대화창 v2 (`src/client/ui/DialogueBox.js` 개편)

- **2줄 고정 페이징**: 대화창 높이를 2줄로 고정. 긴 텍스트는 페이지 분할, `[Space]`(또는 클릭)로 다음 페이지, 남은 페이지가 있으면 `▼` 표시. 마지막 페이지에서 누르면 종료(선택지 NPC면 선택지로 복귀).
- **LLM 대사도 동일 규칙**: SSE 스트림을 버퍼에 모두 받은 뒤 2줄씩 페이징. 대기 중에는 초상 옆 "…" 생각 중 연출로 체감 지연을 가린다.
- **우측 선택지 버튼**: 대화창 오른쪽 세로 버튼 스택(최대 3개), 키 라벨 병기 — `대화하기 [E]` / `암호 말하기 [F]` / `그만하기 [Esc]`. DOM 오버레이(한글 IME·클릭 처리 때문에 기존과 동일하게 DOM 유지).
- 자유 입력(chat/code 모드), IME 조합 Enter 무시, busy 잠금 등 기존 동작은 유지.

## 4. 스테이지 1 개선

### 4.1 dialogtest 프롬프트 이식 (브랜치 머지 아님, 내용만 이식)

- `src/data/personas.json`: 동료 5인에 `backstory` + `personality` 필드 추가 (master 스키마 유지, `origin/dialongue-test`의 인물 서사 이식).
- `src/data/prompts/wordgen-system.txt`: 브랜치 규칙으로 교체 —
  - 규칙 1: "코드 단어가 실제로 연상시키는 것들을 먼저 떠올리고, 그중 배경상 먼저 눈에 들어오는 것을 골라라" (억지 직업 번역 금지. 배경은 '무엇이 먼저 보이는가'만 바꾼다).
  - 신설 규칙: "성격이 힌트의 직접성을 결정한다" (솔직한 성격 = 명백한 연상 허용, 신중한 성격 = 우회).
  - master의 "후보 3개 → 남들이 가장 안 떠올릴 단어" 절차(현행 규칙 1~3)는 삭제, 획일적 "노골적이면 안 된다"(현행 규칙 6)는 성격별 편차 규칙으로 대체.
- `src/data/prompts/dialogue-system.txt`: `{{persona}}` → `{{backstory}}`/`{{personality}}`, 말투 지침을 성격 기반으로 교체.
- 서버: `ai/wordGen.js`·`ai/dialogue.js`의 변수 전달부 수정, `routes/studio.js`·`studio.html`의 미리보기 변수 목록 갱신.

### 4.2 정답 제출 완화

- 서버 guess 라우트의 접선책 제한 해제 — 모든 동료가 `choiceNpc`로서 `암호 말하기 [F]` 선택지를 가짐.
- 시계 수리공(접선책)의 고유 역할 제거, 일반 동료와 동일 취급.

### 4.3 동료 은신 배치

- 순찰 감지는 원형(반경 150~228px)이므로 기존 지형의 사각지대로 **스폰 좌표만 이동**을 우선. 사각지대가 부족한 곳만 지형 추가 (배경 재굽기 최소화).
- 구체 배치안은 §6.

### 4.4 구제책 (미도입, 재검토 항목)

- 이번에는 넣지 않는다. 플레이테스트에서 정체 사례가 확인되면 후보 순서: 대화 관대화(오답 횟수를 프롬프트에 주입, wordGen 무접촉) → 메타 힌트(글자 수·초성) → 선택지 전환.
- 제약: wordGen 직접성을 올리는 방식은 중복(체포) 폭등 역효과가 실측으로 확인되어 있어 금지. 안전 레버는 대화·판정 쪽만.

## 5. 스테이지 2 개선

### 5.1 성향 판정 강화

- `ai/stance.js`의 인라인 시스템 프롬프트를 `src/data/prompts/mansion-stance.txt`로 추출, 프롬프트 스튜디오에서 튜닝 가능하게.
- anti/pro의 명시적 판정 예시(저항 언급, 신고 위협, 체제 찬양, 밀고 제안 등)를 few-shot으로 추가. "애매하면 neutral" 원칙은 유지하되 **명백한 직접 발언은 반드시 잡히게** 한다.
- `ai/dialogue.js`에 하드코딩된 동료/민간인 연기 지침(`kindBlock`)도 프롬프트 파일로 추출.

### 5.2 프롬프트 체계 통일

- `src/data/mansion.json`의 NPC에도 `backstory`/`personality` 분리 적용, `mansion-dialogue.txt` 변수 교체 — 스테이지 1과 동일 체계.

### 5.3 조사 오브젝트 + 대화 힌트 연동

- 방마다 조사 오브젝트 1~2개 (예: 주방 배급 장부, 세탁실의 얼룩진 제복, 서가의 검열 도서 목록). `mansion.json`에 오브젝트 데이터 추가.
- 조사 시: 짧은 단서 텍스트 표시 + 서버 세션에 단서 플래그 기록.
- 대화 시: 성향 판정기에 "발견한 단서 목록"을 컨텍스트로 전달, 출력 스키마에 `usedClue` 추가. 플레이어가 대화에서 해당 화제를 의미 있게 꺼내면 **호감도 +1 보너스** (단서당·NPC당 1회 — 소진 플래그로 반복 파밍 차단). NPC 대화 프롬프트에도 단서 컨텍스트를 주입해 NPC가 그 화제에 실제로 반응.
- 효과: "탐색 → 대화 소재 획득 → 호감도" 루프가 생겨, 호감도 3 도달까지 무작정 대화만 반복하는 단조로움을 깬다. 기존 호감도 루프(anti 발언 = +1)는 그대로 유지.

### 5.4 문·문서 연출

- 실험실 문: `door` 노드로 전환 (§2 표 참조).
- 기밀 문서: `document` 노드 — 종이 질감 전용 패널로 열람 (클리어 조건 로직은 현행 유지).

## 6. 맵 제안안 (기획자 논의용)

### S1 동료 은신 배치

상주 순찰 3루트(대로·교차로·부두)의 원형 감지가 닿지 않는 포켓으로:

| 동료 | 배치 제안 |
|---|---|
| 시계 수리공 | 시계탑 골목 안쪽 |
| 하녀 | 저택가 뒷문 처마 밑 |
| 기술자 | 기관실 수로 옆 |
| 밀수꾼 | 부두 창고 뒤 |
| 악사 | 극장 뒷골목 |

- 원칙: 접근하려면 순찰 경로를 최소 한 번 가로지르게 해 긴장 유지. 은신처 자체는 안전지대.
- 좌표는 tilemap-studio에서 확정, 감지 반경 겹침 검사를 스크립트로 자동화.

### S2 오브젝트 배치

- 오브젝트는 관련 NPC의 방 **반대편**에 배치 — 방을 가로지르며 탐색하게 유도.

## 7. 검증

- wordgen 프롬프트 교체 후 `exp:diff` 중복률 재측정 (**필수** — 통과 기준: 기존 실측 대비 체포 유발 중복률이 급증하지 않을 것).
- 성향 판정: 프롬프트 스튜디오로 직접 발언 케이스(저항 언급/신고 위협/체제 찬양) 테스트.
- 기존 smoke 스크립트 통과.
- 세 씬 마이그레이션 후 회귀 확인: 검문 2단, 구출, 열쇠→문, 문서 클리어 경로.

## 8. 일정과 컷라인 (기능 동결 8/7)

우선순위:

1. **P0** 공통 인터랙션 레이어 + 대화창 v2 (기획 연출 스펙의 핵심)
2. **P1** S2 조사 오브젝트 + 성향 판정 강화
3. **P2** S1 dialogtest 이식 + 정답 제출 완화
4. **P3** S1 동료 은신 배치

일정이 밀리면 컷 순서: 은신 배치 → 문서 패널 연출 간소화(대화창 재활용) → S2 오브젝트 방당 1개로 축소.
