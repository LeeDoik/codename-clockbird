# UI 아트 사양서 — 무대 · 단서 수첩 · 로딩

`docs/` 밖 목업 영상(`20260804-0659-33.4329308.mp4`, 7.5초)에서 읽어 낸 화면을
지금 게임에 붙이기 위한 작업 지시서다. 굽는 도구는 `scripts/gen-ui-assets.js`
(PixelLab API), 프롬프트는 그 파일이 단일 출처다 — **여기에는 프롬프트를 복사해
두지 않는다.** 두 군데 적으면 반드시 갈라진다.

앞선 문서와의 관계: `design/UI/pixellab-ui-prompts.md` 는 PixelLab **웹앱의
Create UI** 로 대화창 액자를 뽑은 기록이고, 이 문서는 같은 화풍을 **API** 로
잇는다. 재작업 기준(§7)과 색값은 그쪽을 그대로 따른다.

---

## 1. 영상이 무엇이었나

두 토막이다.

| 구간 | 내용 |
| --- | --- |
| 0.0 – 5.0초 | **목업** — 수류탄 투척 미니게임을 그림으로 그린 것 |
| 5.0 – 5.5초 | **지금 게임** — 같은 판이 CSS 껍데기로 도는 화면 |
| 5.5초 – | 검정 |

목업 쪽은 다시 두 단계로 나뉜다. `grenadeThrow.js` 의 두 단계와 정확히 같다.

1. **충전** — 가운데 원형 톱니 메달(`SPACE`)을 연타, 오른쪽 세로 게이지가 주황으로
   차오르고 양옆에 파란 번개가 감긴다. 왼쪽에 수류탄 쥔 손 그림.
2. **투척** — 위쪽 가로 트랙에 빨강/초록 구간, 놋쇠 추가 왕복. 가운데 버튼이
   사각으로 낮아진다. 좌우에 던지는 소년과 순찰 로봇.

**목업을 그대로 베끼지 않는다.** 토대로 삼아 밀고 나간 지점은 §4 에 적었다.

## 2. 지금 게임에 이미 있는 것

무대 배치는 **이미 다 짜여 있다.** `#minigame-card.stage` (index.html) 가 제목
액자·시계 액자·경고 띠·무대를 그리드로 앉히고, `.gr-*` 가 메달 버튼·게이지·트랙·
추를 CSS 로 그린다. `grenadeThrow.js` 는 `/ui/grenade-throw.png` 와
`/ui/guard-robot.png` 를 이미 불러오고 있다 — **파일이 없어서 `onerror` 로 숨는
중이다.**

그래서 이 작업은 새 화면을 짜는 일이 아니라 **CSS 그라디언트를 그림으로 갈아
끼우는 일**이다. 붙이는 자리는 부품마다 `gen-ui-assets.js` 의 `target` 에 적혀 있다.

## 3. PixelLab 이 못 하는 것 — 먼저 정하고 들어간다

목업의 인물·배경은 **페인팅**이다. PixelLab 은 픽셀아트만 만든다. 두 갈래 중
하나를 골라야 하는데, 이 문서는 **픽셀아트**를 택했다.

- 게임 세계(맵 타일·NPC 스프라이트·`dialogue-frame.png`)가 전부 픽셀아트다.
  무대만 페인팅이면 미니게임이 열릴 때마다 다른 게임이 끼어드는 것처럼 보인다.
- 예외는 초상(`public/portraits/*.png`)뿐이다. 그건 대화창 안에 갇혀 있고
  액자가 경계를 그어 주지만, 무대 그림은 액자 없이 배경과 맞닿는다.

목업의 페인팅 질감을 굳이 살리려면 초상을 뽑은 도구로 따로 굽고 이 파이프라인
바깥에 둬야 한다. 그때도 UI 부품(액자·버튼·게이지)만은 픽셀아트로 남긴다 —
그쪽은 대화창과 한 세트여야 한다.

## 4. 목업에서 밀고 나간 지점

| 무엇 | 왜 |
| --- | --- |
| **명중/빗나감 그림 추가** (`hit-burst` · `fizzle`) | 목업은 판이 도는 동안만 보여 준다. 실제로는 판정 뒤 800ms 동안 "성공"/"실패" 글자만 뜨는데(`MinigamePanel.run`), 12초를 두들긴 끝이 글자 두 자라 손맛이 거기서 끊긴다 |
| **번개를 부품으로 분리** (`lightning`) | 목업은 게이지에 번개가 붙어 있다. 붙여서 구우면 충전량에 따라 세지는 연출을 못 한다 — 따로 구워 겹치고 CSS 로 깜빡인다 |
| **트랙 안쪽을 굽지 않음** | 초록 구간의 위치·폭이 판마다 무작위다(`zoneStart`·`zoneW`, 경계 수위에 따라 좁아진다). 그림으로 박으면 난이도 곡선이 죽는다 — 액자만 굽고 안은 CSS 로 남긴다 |
| **액자 하나를 셋이 공유** (`stage-frame`) | 목업은 제목·시계·경고 띠의 액자가 미묘하게 다르다. 셋을 따로 구우면 톤이 갈리고 다시 구울 때마다 셋을 맞춰야 한다. 9분할이라 한 장이 세 크기를 다 덮는다 |

## 5. 부품 목록과 현재 상태

`node scripts/gen-ui-assets.js --list` 가 항상 최신이다.

**2026-08-05 — 22장을 굽고 전부 화면에 붙였다** (무대 17 + 단서 수첩 2 + 로딩 3).

`clock-face` 는 눈금에 가짜 숫자가 남았고 `lightning` 은 줄기에 동그란 방울이
섞였다. 둘 다 깜빡이며 스쳐 가는 자리라 그대로 뒀다.

### 낱말 하나가 옵션 셋을 이긴 자리

`stage-bg` 는 두 번 **원근 복도**로 나왔다. 무대는 좌우에 인물을 세우는 옆보기
배경이라 복도면 인물이 공중에 뜬다. `flat side view` 와 `no vanishing point` 를
못박고 negative 에 `one point perspective` 까지 넣었는데 소용없었다.

문제는 옵션이 아니라 낱말이었다. **모델은 `street` 를 원근으로만 그린다.** 거리를
아예 빼고 `a row of ruined building facades`(정면에서 본 건물 벽면 한 줄)로 부르니
한 번에 평면이 나왔다. 덤으로 그 그림은 **가로로 되풀이해도 안 망가진다** —
`background-repeat: repeat-x` 라 무대가 아무리 넓어도 늘어나거나 잘리지 않는다.

프롬프트가 안 먹을 때는 옵션을 더 얹기 전에 **낱말을 의심하는 편이 빠르다.**
`needle`(→ 괘종시계 탑)과 `clue-clip`(→ 철사 클립)도 같은 함정이었다.

## 5-1. 단서 수첩 ([C], 스테이지 1)

종이는 그림이 맡고 **구김은 CSS 가 계속 맡는다.** 구김(`--crumple`)은 무늬가
아니라 연출이라서다 — 수첩을 열면 360ms 에 걸쳐 골이 벌어지며 옅어진다
(`clue-flatten`). 그림에 구우면 움직이지 못한다.

⚠ 종이를 다시 구우면 **`#cluebook-card` 의 padding 을 다시 재야 한다.** 찢긴
가장자리가 안쪽으로 깊게 파고들어서, 여백이 모자라면 글자가 톱니에 물려 잘린다
(clip-path 시절엔 가장자리가 곧은 선이라 없던 문제다). 지금 값은 좌우 84 ·
위아래 42 이고, 바닥 안내문은 88 위에 앉아 있다.

## 5-2. 씬 전환 로딩 (튜토리얼 → 거리)

예전 화면은 CSS 로 그린 원반 하나에 깜빡이는 점 셋이었다. 움직이긴 했지만
**어느 게임에 갖다 놔도 어울리는 로딩 스피너**였다. 제목이 "태엽새"인데
시계가 그리다 만 원이면 아깝다.

세 층으로 다시 짰다.

| 층 | 무엇 |
| --- | --- |
| 뒤 | `cog-large` 가 24초에 한 바퀴, 화면 오른쪽 아래에 반쯤 걸쳐 |
| 가운데 | `watch-face` 회중시계. **바늘만 CSS** — 돌아야 하니 그림에 못 굽는다 |
| 아래 | `tape-strip` 이 가로로 흐른다 |

테이프는 장식이 아니다. 이 화면이 떠 있는 동안 뜨는 부제가 **"동료들의 암호를
수신하고 있다"** 이므로, 테이프가 지나가야 그 말이 그림과 같은 소리를 한다.

### ⚠ 바늘 축은 그림 한가운데가 아니다

회중시계는 위에 용두와 고리가 얹혀 있어 문자판이 아래로 밀린다. 실측
**좌 50.3% · 상 56.1%** 이고, 50% 로 두면 바늘이 문자판 위쪽에 박혀 돈다.

재는 법: 문자판을 가로지르는 **가장 긴 어두운 구간**을 찾는다. 그 줄이 원의 중심
높이고, 구간의 한가운데가 중심 가로 위치다. **무게중심으로 재면 안 된다** —
테두리 그늘과 용두 그림자가 아래로 끌어당겨 3.5% 어긋난 값(59.6%)이 나왔다.

### 배경 층은 opacity 만으로 안 눌린다

`cog-large` 는 살이 호박색이라 흐리게 깔아도 그 부분만 또렷하게 떠서 눈이 그리로
간다. `brightness(0.45) saturate(0.5)` 를 같이 걸어야 배경이 된다. `tape-strip` 도
종이가 크림색이라 0.5 로는 화면을 가로지르는 흰 띠가 된다 (지금 0.26).

## 6. 9분할 액자는 가운데가 비어야 한다

`stage-frame` · `track-frame` · `gauge-frame` 은 `border-image` 로 쓰되 slice 에
**`fill` 을 붙이지 않는다.** 붙이면 가운데까지 그려져 트랙의 빨강/초록과 게이지
칸을 덮는다. 반대로 `space-plate` 와 `gauge-cell` 은 판이 곧 배경이라 `fill` 이
필요하다 — 빼면 뚫려 보인다 (`button.png` 가 이미 그렇게 쓰인다).

```css
/* 예: 무대 액자 — slice 값은 받은 그림의 테두리를 재서 정한다 (아래 §7) */
#minigame-card.stage #minigame-head {
  border: calc(28 * var(--s)) solid transparent;
  border-image: url('/ui/stage-frame.png') 30 / calc(28 * var(--s)) / 0 round;
  image-rendering: pixelated;
  background: linear-gradient(180deg, #241a12, #14100b); /* 안쪽은 그대로 둔다 */
}
```

변은 `stretch` 가 아니라 **`round`** 다. 늘이면 리벳 한 줄이 6배로 늘어나 그냥
줄이 된다 — 대화창에서 이미 겪었다(index.html `#dialogue::before` 의 주석).

## 7. 받은 뒤에 할 일

1. **눈으로 거른다.** `design/UI/pixellab-out/<id>.preview8x.png` 가 8배 확대본이다
   — 부품이 48~320px 라 1:1 로는 리벳이 붙었는지 못 본다. 기준은
   `pixellab-ui-prompts.md` §7 의 표 그대로고, 걸리면 **프롬프트를 고치지 말고
   그대로 다시 굴린다.** 문장을 손대면 그 부품만 화풍이 갈라진다.
2. **반입한다.** `node scripts/import-ui-assets.js` 가 배경을 벗기고 여백을 잘라
   `public/ui/` 에 넣는다. §9 참고.
3. **slice 값을 잰다.** `ui-assets.js` 의 `slice` 는 제안일 뿐이다. 실제 테두리
   두께를 재기 전에는 확정할 수 없다.

## 8. 굽는 법

`.env` 에 키를 넣는다. 두 이름 중 아무거나 받는다 — `PIXELLAB_API_KEY`(이 저장소의
`ANTHROPIC_API_KEY` 와 같은 규칙) 또는 `PIXELLAB_SECRET`(공식 SDK 가 쓰는 이름).

```
PIXELLAB_API_KEY=<키>
```

```bash
node scripts/gen-ui-assets.js --list          # 목록
node scripts/gen-ui-assets.js --dry --all     # 보낼 요청만 확인 (돈 안 든다)
node scripts/gen-ui-assets.js stage-frame     # 한 장만
node scripts/gen-ui-assets.js --all           # 전부
node scripts/import-ui-assets.js              # 거른 뒤 public/ui/ 로
```

파일 셋의 역할이 갈려 있다.

| 파일 | 몫 |
| --- | --- |
| `scripts/ui-assets.js` | 부품 표 — 치수·프롬프트·팔레트. **프롬프트를 고칠 자리는 여기뿐이다** |
| `scripts/gen-ui-assets.js` | API 에 보내고 받아 적는다 |
| `scripts/import-ui-assets.js` | 배경 벗기고 잘라 `public/ui/` 에 넣는다 |

## 9. 반입이 하는 일 — 그리고 왜 필요한가

받은 그대로는 두 가지가 안 맞는다.

1. **배경이 불투명하게 온다.** `no_background: true` 를 줘도 인물처럼 큰 그림은
   회갈색 판을 깔고 나온다. 그대로 얹으면 무대 위에 네모난 판이 뜬다.
2. **여백이 제각각이다.** 같은 부품을 다시 구우면 물건이 프레임 안에서 몇 픽셀씩
   옮겨 앉는다. CSS 로 위치를 맞춘 뒤 다시 구우면 그만큼 어긋난다.

배경은 **가장자리에서 흘려보내(flood fill)** 가려낸다. "가장 많이 쓰인 색을
지운다"는 못 쓴다 — 로봇은 몸통이 화면의 절반이라 몸이 지워진다.

⚠ **그 번짐이 몸통을 먹을 수 있다.** 1차에서 `gauge-frame` 이 통째로 날아갔다 —
하우징의 검은 쇠 색이 배경색과 거의 같아 번짐이 몸까지 먹고 뼈대만 남겼다.
그래서 액자에도 `no_background: true` 를 붙여 **모델이 아예 배경을 안 그리게**
했고, 반입 쪽에는 90% 넘게 벗겨지면 경고를 찍게 해 뒀다. 배경 그림처럼 판
전체가 그림인 것은 표에 `opaque: true` 로 표시해 아예 손대지 않는다.
